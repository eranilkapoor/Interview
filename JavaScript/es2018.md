# ES2018 (ES9)

ES2018 rounded out several features that had been introduced incompletely in earlier releases and added meaningful new capabilities of its own. Its most broadly-used additions are the **spread and rest operators for object literals** (`{...obj}` for shallow-copying/merging objects, and `const { a, ...rest } = obj` for destructuring "everything else" into a new object) — extending syntax that ES2015 had only supported for arrays/function arguments (see [spread-operator.md](./spread-operator.md), [rest-parameter.md](./rest-parameter.md)). It also finalized **`for await...of`** (see [for-await.md](./for-await.md)) for iterating over async iterables, and **asynchronous generators** (`async function*`), which combine generators and `async`/`await` to produce a sequence of asynchronously-resolved values.

Beyond that, ES2018 added `Promise.prototype.finally()` (a callback that runs regardless of whether a Promise fulfills or rejects, ideal for cleanup logic — see [promises.md](./promises.md)), several regular expression improvements (named capture groups like `(?<year>\d{4})`, the `s` "dotAll" flag making `.` match newlines, and lookbehind assertions `(?<=...)`/`(?<!...)`), and `Object.prototype`'s remaining spec cleanups around own-property enumeration order.

## Examples

```js
// Object spread and rest
const defaults = { theme: 'light', retries: 3 };
const overrides = { theme: 'dark' };
const merged = { ...defaults, ...overrides }; // object spread
console.log(merged); // { theme: 'dark', retries: 3 }

const { theme, ...rest } = merged; // object rest
console.log(theme, rest); // "dark" { retries: 3 }
```

```js
// Promise.prototype.finally()
function fetchData() {
  return fetch('/api/data')
    .then(res => res.json())
    .catch(err => console.log('Error:', err.message))
    .finally(() => console.log('Request finished — hide loading spinner here'));
}
```

```js
// Named capture groups in regular expressions
const dateString = '2024-03-15';
const match = dateString.match(/(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/);
console.log(match.groups.year, match.groups.month, match.groups.day); // "2024" "03" "15"
```

## Common Pitfalls / Gotchas

- Assuming object spread (`{...obj}`) performs a deep copy — like array spread, it's shallow; nested objects remain shared references.
- Forgetting object rest (`const { a, ...rest } = obj`) must be the *last* pattern in the destructuring — same positional constraint as array/function rest parameters.
- Using `.finally()` and expecting it to receive the resolved value or rejection reason as an argument — it deliberately receives no arguments at all, since its purpose is cleanup that should run identically regardless of the outcome.
- Confusing named capture groups' `match.groups.name` access with numbered capture groups (`match[1]`) — named groups are an additive convenience, not a replacement; both remain available on the same match result.

## Interview Questions & Answers

**Q: What object-related features did ES2018 add, and what were they modeled after?**
A: Object spread (`{...obj}`) and object rest (`const { a, ...rest } = obj`) — extending the array/function-argument spread and rest syntax that ES2015 introduced, to work with plain object literals and destructuring as well.

**Q: What does `Promise.prototype.finally()` provide that `.then()`/`.catch()` alone didn't cleanly support?**
A: A way to run cleanup logic (hiding a loading indicator, closing a connection) that should execute regardless of whether the Promise fulfilled or rejected, without needing to duplicate that cleanup code in both the fulfillment and rejection handlers separately.

**Q: What are named capture groups in regular expressions, and why are they useful?**
A: `(?<name>...)` syntax lets you label a capture group and access its matched value via `match.groups.name` instead of a numbered index (`match[1]`), making regex-based extraction code significantly more readable and less fragile to reordering of the groups within the pattern.
