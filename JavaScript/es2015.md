# ES2015 (ES6)

ES2015 (also called ES6) is the single largest update to JavaScript in the language's history, released in June 2015 after roughly six years without a major revision. It fundamentally modernized how JavaScript is written, introducing features that are now considered basic, everyday syntax: `let`/`const` (block-scoped variable declarations, see [let-and-const.md](./let-and-const.md)), `class` syntax (sugar over prototype-based inheritance, see [classes.md](./classes.md)), arrow functions (see [arrow-function.md](./arrow-function.md)), template literals (backtick strings supporting interpolation and multi-line text), destructuring assignment, default/rest parameters, and the spread operator.

Beyond syntax, ES2015 introduced entirely new capabilities: **Promises** (a native, standardized way to represent asynchronous results, replacing ad-hoc callback patterns — see [promises.md](./promises.md)), **modules** (native `import`/`export` syntax, see [native-es-module.md](./native-es-module.md)), **generators** (`function*`/`yield`, see [generators.md](./generators.md)), **`Symbol`** (a new primitive type for unique identifiers), and new built-in collection types **`Map`** and **`Set`** (see [set-map.md](./set-map.md)) offering dedicated, more appropriate alternatives to abusing plain objects/arrays for key-value storage and uniqueness respectively.

ES2015 also marked TC39's shift to an annual release cadence for the specification going forward — rather than waiting years for another single "big bang" release, smaller, incremental feature sets would ship every year afterward (ES2016, ES2017, and so on), which is why ES2015 remains, by a wide margin, the most feature-dense single release in JavaScript's history.

## Examples

```js
// A snapshot of ES2015's core new syntax, all in one place
class Person {
  constructor(name, ...hobbies) { // classes + rest parameters
    this.name = name;
    this.hobbies = hobbies;
  }
  introduce() {
    return `Hi, I'm ${this.name}. I enjoy: ${this.hobbies.join(', ')}`; // template literals
  }
}
const { name, hobbies } = new Person('Anil', 'reading', 'coding'); // destructuring
console.log(name, hobbies); // "Anil" ["reading", "coding"]

const greet = (person) => person.introduce(); // arrow function
console.log(greet(new Person('Sunita', 'painting')));
```

```js
// Promises and let/const scoping, both new in ES2015
function delay(ms, value) {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}
delay(100, 'done').then(result => console.log(result)); // "done"

for (let i = 0; i < 3; i++) { // let: proper per-iteration block scoping
  setTimeout(() => console.log(i), 0); // 0 1 2 — correct, unlike the old `var` behavior
}
```

```js
// Map and Set — new collection types
const uniqueTags = new Set(['js', 'web', 'js']);
console.log(uniqueTags.size); // 2 — duplicates automatically ignored

const userRoles = new Map([['anil', 'admin'], ['sunita', 'editor']]);
console.log(userRoles.get('anil')); // "admin"
```

## Common Pitfalls / Gotchas

- Assuming every ES2015 feature is transpiled/polyfilled identically everywhere — some (like `Proxy`, generators' full semantics) are difficult or impossible to fully polyfill for older engines, unlike simpler syntax-only features Babel can transform directly.
- Continuing to use `var` out of habit in new code — `let`/`const` fix real scoping footguns `var` has, and virtually all modern style guides recommend avoiding `var` entirely.
- Forgetting `class` in ES2015 is sugar over the pre-existing prototype system, not a brand-new inheritance model (see [classes.md](./classes.md)) — this misconception leads to confusion about topics like static methods and `super`.
- Treating ES2015 as "modern JavaScript" in an unqualified sense a decade-plus later — many more features have shipped since (ES2016 through ES2023+), and some ES2015-era idioms (like the module pattern with IIFEs) are now themselves considered legacy relative to native modules/classes.

## Interview Questions & Answers

**Q: Why is ES2015 considered such a landmark release compared to other yearly ECMAScript versions?**
A: It introduced an unusually large, foundational set of features all at once — block-scoped variables, classes, arrow functions, template literals, destructuring, default/rest/spread, Promises, modules, generators, `Symbol`, `Map`/`Set` — effectively modernizing the entire language after nearly six years without a major update. Every ECMAScript release since has been comparatively incremental by design, following TC39's new yearly release cadence established starting with ES2015.

**Q: Name three ES2015 features that directly addressed long-standing JavaScript pain points, and what each one fixed.**
A: `let`/`const` fixed `var`'s lack of block scoping and hoisting confusion. Promises fixed callback hell's nested, hard-to-manage asynchronous code. Native modules (`import`/`export`) fixed the lack of a standardized module system, which had previously fragmented into competing formats like CommonJS and AMD.

**Q: Is `class` syntax in ES2015 a fundamentally new inheritance mechanism?**
A: No — it's syntax sugar over JavaScript's existing prototype-based inheritance system. Methods defined in a class body are placed on the class's `.prototype`, exactly as if manually assigned to a constructor function's `.prototype` the pre-ES2015 way.
