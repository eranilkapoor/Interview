# ES2019 (ES10)

ES2019 added a collection of practical, everyday utility improvements. **`Array.prototype.flat(depth)`** flattens nested arrays up to the given depth (default `1`), and **`Array.prototype.flatMap(fn)`** combines `map()` followed by a single-level `flat()` in one efficient pass — useful whenever a mapping function itself produces arrays that should be merged into the outer result rather than nested. **`Object.fromEntries(entries)`** does the inverse of `Object.entries()`, building a plain object back up from an iterable of `[key, value]` pairs — particularly handy for converting a `Map` into a plain object, or for transforming an object's entries and reconstructing it afterward.

String methods `String.prototype.trimStart()`/`trimEnd()` provide directional whitespace trimming (as opposed to `trim()`, which strips both ends) — standardizing names that had existed non-standardly as `trimLeft()`/`trimRight()` in some engines beforehand. `Symbol.prototype.description` exposes a Symbol's descriptive label directly as a readable property (previously only inspectable indirectly via `.toString()`). `Array.prototype.sort()` was specified to be **stable** (equal elements retain their relative original order after sorting — previously left as implementation-defined, causing inconsistent behavior across engines). `try { } catch { }` now supports an **optional catch binding** — omitting the error parameter entirely when you don't need to inspect it. `JSON.stringify()` was also fixed to always produce well-formed Unicode (previously could produce invalid surrogate pairs for certain characters).

## Examples

```js
// flat() and flatMap()
const nested = [1, [2, 3], [4, [5, 6]]];
console.log(nested.flat());     // [1, 2, 3, 4, [5, 6]] — default depth 1
console.log(nested.flat(2));    // [1, 2, 3, 4, 5, 6] — depth 2 flattens fully here

const sentences = ['hello world', 'foo bar'];
console.log(sentences.flatMap(s => s.split(' '))); // ["hello","world","foo","bar"] — map + flatten in one step
```

```js
// Object.fromEntries() — the inverse of Object.entries()
const map = new Map([['a', 1], ['b', 2]]);
const obj = Object.fromEntries(map);
console.log(obj); // { a: 1, b: 2 }

// Practical use: transforming an object's entries, then reconstructing it
const prices = { apple: 1, banana: 2 };
const doubled = Object.fromEntries(
  Object.entries(prices).map(([key, value]) => [key, value * 2])
);
console.log(doubled); // { apple: 2, banana: 4 }
```

```js
// Optional catch binding, and stable sort
try {
  JSON.parse('{invalid}');
} catch {
  console.log('Parsing failed'); // no need to capture/name the error if unused
}

const items = [{ name: 'a', order: 1 }, { name: 'b', order: 1 }, { name: 'c', order: 0 }];
console.log(items.sort((x, y) => x.order - y.order));
// [{c,0}, {a,1}, {b,1}] — 'a' and 'b' (equal order) reliably keep their original relative order
```

## Common Pitfalls / Gotchas

- Forgetting `flat()`'s default depth is `1`, not full/infinite — for deeply nested arrays of unknown depth, use `flat(Infinity)`.
- Confusing `flatMap()` with `map().flat()` performance-wise — they're logically equivalent, but `flatMap()` does it in a single, more efficient pass, avoiding creating an intermediate nested array.
- Assuming `Array.prototype.sort()` was always stable — it only became a specification *guarantee* in ES2019; code relying on stability for correctness in environments/engines older than that guarantee could behave inconsistently.
- Using `Object.fromEntries()` on a `Map` with non-string keys and expecting them to survive as-is — plain object keys are always coerced to strings (or kept as Symbols), so non-string, non-Symbol Map keys lose their original type when converted this way.

## Interview Questions & Answers

**Q: What's the difference between `Array.prototype.flat()` and `Array.prototype.flatMap()`?**
A: `flat(depth)` flattens nested arrays up to the specified depth (default 1). `flatMap(fn)` maps each element with `fn` and then flattens the result by exactly one level, in a single combined operation — equivalent to `array.map(fn).flat()`, but done more efficiently in one pass, and specifically useful when your mapping function returns arrays you want merged into the outer result.

**Q: What does `Object.fromEntries()` do, and what's a practical use case for it?**
A: It builds a plain object from an iterable of `[key, value]` pairs — the inverse of `Object.entries()`. A common use case is converting a `Map` back into a plain object, or transforming an object's key-value pairs (via `map`/`filter` on its entries) and reconstructing a new object from the result.

**Q: Why did ES2019 standardizing `Array.prototype.sort()` as stable matter?**
A: Before ES2019, the relative order of equal elements after sorting was left as implementation-defined, meaning different JavaScript engines could produce different (both technically "correct") orderings for elements considered equal by the comparator — a source of subtle cross-engine inconsistency. Guaranteeing stability means equal elements always retain their original relative order, making sort behavior fully predictable everywhere.
