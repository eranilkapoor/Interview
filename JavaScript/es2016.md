# ES2016 (ES7)

ES2016 was the first release under TC39's new yearly cadence following ES2015's massive overhaul, and — by deliberate design — it was tiny by comparison, shipping just two notable additions: the **exponentiation operator** (`**`) and **`Array.prototype.includes()`**. This modest scope was intentional: rather than waiting years to bundle many features into one release (as had happened before ES2015), TC39 committed to shipping whatever features had actually finished the standardization process each year, even if that meant a very small release.

The exponentiation operator `**` provides concise syntax for exponentiation, equivalent to `Math.pow(base, exponent)` but as an infix operator, consistent with how `+`, `-`, `*`, `/` already worked, and supporting a compound assignment form (`x **= 2`). `Array.prototype.includes(value)` provides a direct, readable way to check whether an array contains a value, returning a boolean — a cleaner alternative to the previously-common `array.indexOf(value) !== -1` idiom, and with one meaningful behavioral difference: `includes()` correctly matches `NaN` (using the `SameValueZero` algorithm), whereas `indexOf()` cannot find `NaN` at all (since `indexOf` uses strict equality, and `NaN !== NaN`).

## Examples

```js
// Exponentiation operator
console.log(2 ** 10);      // 1024, equivalent to Math.pow(2, 10)
console.log(2 ** 0.5);     // 1.4142135623730951 (square root of 2)

let base = 3;
base **= 3; // compound assignment: base = base ** 3
console.log(base); // 27
```

```js
// Array.prototype.includes() vs indexOf()
const numbers = [1, 2, 3, NaN];
console.log(numbers.indexOf(NaN));  // -1 — indexOf CANNOT find NaN (uses strict equality)
console.log(numbers.includes(NaN)); // true — includes correctly finds it (SameValueZero)

console.log([1, 2, 3].includes(2));   // true
console.log([1, 2, 3].indexOf(2) !== -1); // true — the older, clunkier equivalent
```

```js
// includes() reads more clearly in boolean contexts than indexOf comparisons
function hasPermission(userRoles, requiredRole) {
  return userRoles.includes(requiredRole); // clean, direct boolean intent
}
console.log(hasPermission(['admin', 'editor'], 'admin')); // true
```

## Common Pitfalls / Gotchas

- Forgetting `includes()` cannot distinguish `+0` and `-0` from each other by design (it treats them as equal, per `SameValueZero`), which rarely matters in practice but is a subtle edge case worth knowing.
- Assuming `**` and `Math.pow()` are always perfectly interchangeable in every edge case — they're specified to behave identically, so this is generally safe, but `**` is simply the more modern, readable choice for new code.
- Underestimating how small ES2016 was and assuming every yearly ECMAScript release is similarly large — ES2016 set the precedent that releases can be very modest; feature size varies considerably year to year based on what's actually finished the standardization process (see [es2015.md](./es2015.md) for contrast).

## Interview Questions & Answers

**Q: What two features did ES2016 introduce, and why was the release so much smaller than ES2015?**
A: The exponentiation operator (`**`) and `Array.prototype.includes()`. It was small because TC39 switched to a yearly release cadence starting with ES2015, shipping whatever features had finished the standardization process by each year's cutoff — some years simply have fewer ready features than others, and ES2016 happened to be a light year immediately following ES2015's unusually large release.

**Q: Why would you prefer `array.includes(value)` over `array.indexOf(value) !== -1`?**
A: It's more directly readable (expresses boolean intent clearly rather than an index comparison), and it correctly handles `NaN` — `includes()` can find `NaN` in an array using the `SameValueZero` comparison algorithm, while `indexOf()` cannot, since it relies on strict equality and `NaN !== NaN`.

**Q: What comparison algorithm does `includes()` use, and how does that differ from `===`?**
A: `SameValueZero`, which behaves like `===` for almost every value, except it treats `NaN` as equal to itself (`NaN` matches `NaN`) and does not distinguish `+0` from `-0` (treating them as equal) — both edge cases `===` handles differently.
